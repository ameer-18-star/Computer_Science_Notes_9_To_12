4.1 Computational Thinking

Q1. Define Computational Thinking.

Computational Thinking (CT) is a problem-solving process that involves a set of skills and techniques to solve complex problems in a way that can be executed by a computer. It is not limited to computer science and can be applied in everyday life, biology, mathematics, and other fields. Its key components include decomposition, pattern recognition, abstraction, and algorithms.

Q2. What is decomposition? Give one example.

Decomposition is the method of breaking down a complicated problem into smaller, more manageable components. For example, building a birdhouse can be decomposed into steps: designing, gathering materials, cutting wood, assembling, painting, and installing. This makes even complex tasks easier to handle one at a time.

Q3. What is pattern recognition in computational thinking?

Pattern recognition involves identifying and understanding regularities or patterns within a set of data or problems. For example, the area of squares follows a pattern where each area can be found by adding consecutive odd numbers (e.g., 1+3+5 = 9 for side length 3). Recognizing such patterns helps create faster and more efficient solutions.

Q4. Define abstraction with an example.

Abstraction is the process of hiding complex details while exposing only the necessary parts, helping to reduce complexity. For example, making a cup of tea can be described at a high level as: boil water, add tea, wait, pour — without mentioning the complex chemistry or physics involved. It allows us to focus on the important aspects of a problem.

Q5. What is an algorithm? Give a real-life example.

An algorithm is a precise, step-by-step set of instructions followed to achieve a specific goal. A real-life example is a recipe for baking a cake, which includes steps like preheating the oven, mixing ingredients, and setting a timer. Algorithms are used everywhere — from cooking to navigation directions to computer programs.

4.2 Principles of Computational Thinking

Q6. What is meant by "Problem Understanding" in computational thinking?

Problem understanding involves identifying the core issue, defining the requirements, and setting the objectives before attempting a solution. It is the first and most important step in the problem-solving process. Without clearly understanding the problem, any solution designed may be ineffective or incorrect.

Q7. What is problem simplification? Give an example.

Problem simplification involves breaking down a large problem into smaller, more manageable sub-problems. For example, designing a website can be simplified by dividing it into sub-tasks: designing the layout, creating content, and coding the functionality. This approach makes large problems easier to solve step by step.

Q8. What is "Solution Selection and Design"?

Solution selection and design involves evaluating different approaches to solve a problem and choosing the most efficient one. After selecting the best approach, a detailed plan or algorithm is designed to implement the solution. This ensures the final solution is both effective and optimized.

4.3 Algorithm Design Methods

Q9. What are flowcharts and why are they important?

Flowcharts are visual representations of the steps in a process or system, depicted using different symbols connected by arrows. They are important because they provide clarity, aid communication, help in problem-solving by identifying bottlenecks, and serve as documentation. They are widely used in computer science, engineering, and business.

Q10. Name and describe any THREE flowchart symbols.

  • Oval (Terminal): Represents the start or end of a process, labeled "Start" or "End."
  • Rectangle (Process): Represents a process, task, or operation to be performed.
  • Diamond (Decision): Represents a decision point where the flow branches based on a yes/no or true/false condition.

Q11. What is pseudocode and how does it differ from actual code?

Pseudocode is a method of representing an algorithm using simple, informal language that combines the structure of programming with the readability of plain English. Unlike actual code, pseudocode cannot be run on a computer — it is used to plan and explain the logic of an algorithm. It allows programmers to focus on problem-solving without worrying about programming language syntax.

Q12. List THREE benefits of using pseudocode.

  1. Clarity: It helps understand the logic of the algorithm without worrying about syntax.
  2. Planning: It allows programmers to outline their thoughts and plan algorithm steps before coding.
  3. Communication: It is a universal way to convey algorithm steps, making it easier to discuss with team members who may use different programming languages.

4.4 Evaluation Techniques

Q16. What is time complexity? Why is it important?

Time complexity measures how fast or slow an algorithm performs and shows how the running time changes as the size of the input increases. It is expressed using Big O notation such as O(n), O(log n), or O(n²). It is important because it helps compare different algorithms to determine which one is faster and more efficient.

Q17. What is space complexity?

Space complexity measures the amount of memory an algorithm uses relative to the size of its input. It considers both the memory needed to store the input data and any additional memory used during execution. Understanding space complexity helps ensure an algorithm does not use more memory than available.

4.5 Dry Run and Simulation

Q18. What is a dry run? Why is it useful?

A dry run involves manually going through an algorithm or flowchart step-by-step with sample data to identify any errors before running it on a computer. It helps catch logical mistakes early in the development process, saving time and effort. Many professional programmers use dry running as a key debugging technique.

Q20. What is simulation? Give two real-world examples.

Simulation is the use of computer programs to create a model of a real-world process or system to test ideas without needing real-life trials. Two examples are:
1. Weather Forecasting: Meteorologists input data like temperature and humidity into models to predict future weather.
2. Traffic Flow: City planners simulate traffic to see how changes to roads or traffic lights affect the flow of cars.

Q21. List THREE benefits of simulation.

  1. Cost-Effective: It is cheaper and faster to run simulations than real experiments.
  2. Safe: Dangerous situations like fires can be tested without real risk.
  3. Repeatable: The same simulation can be run multiple times with different settings to observe changes.

4.6 LARP

Q22. What is LARP and why is it important?

LARP stands for Logic of Algorithms for Resolution of Problems. It is a fun and interactive way to learn how algorithms work by running them and seeing the results. LARP is important because it helps students understand how algorithms process data, see the effect of different inputs on outputs, and practice writing and improving their own algorithms.

Q23. Write a LARP algorithm to check if a number is even or odd.

  ELSE

  ENDIF

4.7 Error Identification and Debugging

Q25. What are the three types of errors in algorithms? Define each briefly.

  1. Syntax Error: Occurs when something is written incorrectly, such as missing a step or using the wrong symbol. It is the easiest to find.
  2. Runtime Error: Occurs during execution, such as attempting to divide by zero. The algorithm crashes or stops unexpectedly.
  3. Logical Error: Occurs when the algorithm's logic is wrong, causing incorrect results even though the algorithm runs without crashing. It is the hardest to detect.

Q26. Which type of error is hardest to find and why?

Logical errors are the hardest to find because the algorithm still runs successfully without any crash or error message, but produces incorrect results. Since no warning is displayed, the programmer must carefully trace the algorithm's logic to identify where the wrong condition or operation is being used.

Q27. What is debugging?

Debugging is the process of finding and fixing errors (bugs) in an algorithm, flowchart, or program. The term originates from an actual moth (bug) found causing problems in an early computer, which was then "debugged." Techniques like dry runs, reading error messages carefully, and testing with different inputs are used during debugging.

Q28. List the three common error messages in LARP and their meanings.

  1. Missing Step — An important step was forgotten in the algorithm.
  2. Undefined Variable — A variable is being used before it has been defined.
  3. Invalid Operation — An operation not allowed is being performed, such as dividing by zero.

Q29. Why should error messages be read carefully during debugging?

Error messages often tell you exactly where the problem is in the algorithm, saving significant time during debugging. For example, in LARP, a "Missing Step" message immediately tells the programmer that a required step is absent. Carefully reading error messages allows programmers to locate and fix bugs quickly and efficiently.

Q30. What is the origin of the word "debugging"?

The term "debugging" comes from an actual bug — a moth — that was found causing problems inside an early computer. When the moth was physically removed from the machine, the process was called "debugging." Since then, the term has been used to describe the process of finding and fixing errors in programs and algorithms.
